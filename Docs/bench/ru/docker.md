# Решение в Docker

На отборе ваше решение запускается как Docker-образ. Эта страница показывает, как собрать образ и проверить его у себя
в тех же условиях, что на сервере.

## Что нужно

- Docker (на Windows: Docker Desktop с WSL2).
- Из набора участника: папки `bench/template`, `bench/runner`, `bench/docker` и Linux-сборка симулятора `Builds/BenchServer`.
- Образ симулятора `ushqyr-bench-server` и базовый образ `ushqyr-bench-base:cpu`. Их собирает одна команда (см. ниже).

```
pip install ./bench/runner
ushqyr-bench build-images
```

`build-images` берет Linux-сборку симулятора из `Builds/BenchServer`. Командам она выдается готовой вместе с набором
участника; организаторы собирают ее в Unity: меню **Ushqyr / Build / Build Bench Server (Linux)**.

## Шаблон

Скопируйте `bench/template` и пишите свой код в `solution.py`.

| Файл | Что это |
|---|---|
| `Dockerfile` | Как собирается образ. Основа: `ushqyr-bench-base:cpu` (Python 3.11, SDK, NumPy, OpenCV) |
| `solution.py` | Ваше решение. В шаблоне дрон взлетает и висит |
| `requirements.txt` | Дополнительные пакеты Python |

Адрес симулятора и токен приходят в переменных окружения `USHQYR_BENCH_HOST`, `USHQYR_BENCH_PORT`,
`USHQYR_BENCH_TOKEN`. `Sim.connect()` читает их сам. Программа должна завершиться сама, когда попытка закончилась.

## Проверка

```
ushqyr-bench submit-check ./my_solution --track H1_Oval --logs
```

Команда собирает образ, запускает симулятор в режиме соревнования и ваше решение рядом с ним, ждет конца попытки и
печатает результат. Папка попытки (логи, видео, контрольные суммы) появляется в `bench_results`.

Готовый пример: `ushqyr-bench submit-check bench/examples/color_pid`.

## Условия в контейнере

Решение работает в закрытом контейнере. Рассчитывайте на это заранее.

| Условие | Значение |
|---|---|
| Сеть | Только симулятор. Интернета и DNS нет: все пакеты и веса моделей должны быть внутри образа |
| Файлы | Файловая система только для чтения. Писать можно в `/tmp` (256 МБ, в памяти) |
| Пользователь | Не root (uid 10001), без привилегий |
| Память | 4 ГБ |
| Процессор | 4 ядра |
| Процессы | не больше 256 |
| Размер образа | не больше 8 ГБ |
| Видеокарта | нет (по умолчанию) |

Числа в таблице предварительные: окончательные лимиты назначают организаторы.

## Время

| Где запущено | Сколько длится проверка попытки в 120 с |
|---|---|
| Docker Desktop на Windows с видеокартой (проверено на GTX 1650 Ti) | около 4 минут вместе со сборкой образа и записью видео |
| Без видеокарты (программная отрисовка) | около 40 минут на 8 ядрах |

На Windows `submit-check` сам подключает видеокарту к контейнеру симулятора (ключ `--sim-gpu auto`). Без видеокарты
симулятор рисует программно: команда включает самую простую графику и не пишет видео с трассы, иначе попытка шла бы
часами.

На результат скорость не влияет: в синхронном режиме время попытки считается по часам симулятора, и симулятор ждет
вашу команду на каждом шаге.

## Частые ошибки

| Сообщение | Причина |
|---|---|
| `the Docker engine is not running` | Запустите Docker Desktop |
| `the base image ... is not built yet` | Выполните `ushqyr-bench build-images` |
| `the attempt produced no result` | Решение не подключилось или упало. Смотрите вывод с `--logs` |
| `the solution did not exit when the attempt ended` | Программа не завершилась сама после конца попытки |
| Ошибка при `pip install` или загрузке весов во время полета | В контейнере нет интернета. Ставьте все в `Dockerfile` |
