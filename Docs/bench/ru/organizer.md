# Руководство организатора

Как запустить попытку в режиме соревнования, что записывает симулятор, как это проверить и как провести весь отбор
без участия человека. Страницы для команд перечислены в [README.md](README.md).

## Запуск одной попытки

```
Ushqyr.exe -bench -bench-mode competition -bench-team "Team name" -bench-attempt 1 ^
           -bench-track H1_Oval -bench-out D:\qualification\results -bench-key D:\secret\bench.key -bench-exit
```

Затем запустите программу команды. Один запуск это одна попытка.

| Ключ | Что это |
|---|---|
| `-bench` | Открыть AI Bench вместо меню |
| `-bench-mode training\|competition` | По умолчанию `training` |
| `-bench-track <название или файл>` | Готовая трасса по названию или любой файл трассы по пути (так используются скрытые трассы) |
| `-bench-rules <файл>` | Файл правил; у полей, которых в нем нет, остаются значения по умолчанию из `StreamingAssets/Bench/rules.json` |
| `-bench-team`, `-bench-attempt`, `-bench-solution <дайджест>` | Записываются в результат |
| `-bench-out <папка>` | Куда класть папки попыток. Без него: `BenchResults` в папке данных пользователя. В тренировочном режиме попытки записываются, только если этот ключ задан |
| `-bench-key <файл>` | Ключ подписи (не меньше 16 байт чего угодно). Также `USHQYR_BENCH_KEY_FILE`. Без него у попыток есть контрольные суммы, но нет подписи |
| `-bench-ffmpeg <файл>` | ffmpeg для видео. Также `USHQYR_FFMPEG`, `StreamingAssets/Bench/ffmpeg.exe` или PATH. Без ffmpeg попытка записывается без видео |
| `-bench-seed <n>`, `-bench-port <n>`, `-bench-token <текст>` | Зерно шума, порт API, токен, который должна предъявить программа |
| `-bench-listen-all` | Принимать программу с другой машины или из контейнера (по умолчанию: только с этого компьютера) |
| `-bench-exit` | Выйти, когда попытка закончилась и ее файлы записаны |
| `-bench-replay <папка попытки>` | Открыть повтор для судей по попытке |
| `-bench-edit <название или файл>` | Открыть трассу в редакторе трасс |
| `-bench-generate <площадка> <зерно> <сложность> <файл>` | Записать случайную трассу в файл и выйти (площадка `hall` или `parking`, сложность от 1 до 3) |
| `-bench-drone <drone.yaml>` | Лететь на своем дроне команды (класс AI CORE) вместо вупера |
| `-bench-limits <class_limits.json>` | Лимиты класса AI CORE (по умолчанию: файл рядом с трассами) |
| `-bench-dataset <папка>` | Сделать размеченный датасет вместо попытки; вместе с `-bench-dataset-count`, `-bench-dataset-seed`, `-bench-dataset-profile`, `-bench-dataset-masks`. Только тренировочный режим |

В редакторе Unity те же ключи читаются из `UserSettings/bench-args.txt`, по одному ключу или значению в строке.

## Файл правил

Все, что организаторы могут захотеть изменить, лежит в файле правил (`-bench-rules`), а не в сборке. Поля и их
значения по умолчанию записаны в `StreamingAssets/Bench/rules.json`. Чаще всего меняют эти:

| Поле | По умолчанию | Что это |
|---|---|---|
| `time_mode` | `sync` | `sync`: один шаг на команду, результат повторяется. `realtime`: симулятор идет по настенным часам |
| `rc_latency_ms`, `rc_jitter_ms`, `rc_loss_percent` | 10, 0, 0 | Задержка канала управления, добавочная задержка, своя у каждого пакета, доля потерянных пакетов |
| `compute_delay_ms` | 0 | Постоянная задержка, которая заменяет время расчета программы, чтобы в синхронном режиме медленные и быстрые компьютеры летали одинаково |
| `camera_distortion` | 0.18 | Бочкообразное искажение объектива (`k1`); 0 = нет |
| `camera_auto_exposure` | true | |
| `video_range` | 80 | Расстояние в метрах, на котором аналоговое видео хуже всего |
| `lidar`, `lidar_hz` | true, 10 | |
| `randomization` | `none` | `mild` или `strong`: в каждой попытке сцена меняется по зерну (см. «Разброс условий») |

## Трассы и площадки

Две площадки: **зал** (40 × 20 × 8 м) и **паркинг** (60 × 34 м, высота в свету 3,4 м, 28 колонн сеткой, машины
вдоль длинных стен). У каждой есть варианты света (зал: обычный, тусклый, теплый; паркинг: обычный,
тусклый, яркий). Вариант задается в файле трассы.

В `StreamingAssets/Bench/Tracks` лежат шесть готовых трасс:

| Трасса | Площадка | Ворот | Идея |
|---|---|---|---|
| `H1_Oval` | зал | 6 | Плоский овал; следующие ворота всегда видны |
| `H2_Eight` | зал | 8 | Восьмерка с пересечением |
| `H3_Slalom` | зал | 7 | Слалом со смещением и разворот на 180° |
| `X1_Mixed` | зал | 10 | Пять цветов подсветки, рядом крашеные и светящиеся панели тех же цветов |
| `P1_Columns` | паркинг | 6 | Петля вокруг рядов колонн, слабый свет |
| `P2_Maze` | паркинг | 9 | Повороты за колоннами: следующие ворота часто не видны |

В `Docs/bench/track_check.md` записано, что каждая из них проходит проверки и что пилот-оракул пролетает круг.

**Редактор трасс.** В приложении клавиша **T** открывает список трасс (лететь, изменить, новая трасса). В редакторе
ворота перетаскиваются по плану площадки. У каждых ворот задаются цвет подсветки, яркость, режим (горит постоянно
или мигает) и разрешенное направление. Стартовая площадка двигается и поворачивается. Выбираются свет и лимит
времени. Проверки идут прямо во время правки: хватает ли ворот для правила повтора, зазоры до стен, колонн и машин,
место для пролета, расстояния, видны ли ворота со старта. **«Пробный полет (пилот-оракул)»** дает пилоту-оракулу
пролететь трассу и рисует его путь. **«Сохранить»** пишет файл в папку `BenchTracks` в данных пользователя;
**«Экспорт карты»** кладет рядом картинку трассы сверху; **«Полететь»** открывает трассу для программы.

**Пилот-оракул.** Автопилот, который знает истинные координаты. Он нужен только автору трасс (пробные полеты,
проверка трасс, пути камеры для датасетов), в серверную сборку не входит и к API не подключен.

**Случайные трассы.** В редакторе «Случайная трасса» (зерно, уровень от 1 до 3) или из командной строки:
`Ushqyr.exe -bench-generate parking 4217 3 D:\private\HID_p_4217.benchtrack.json`. Одно и то же зерно дает одну и ту
же трассу, и каждая такая трасса проходит проверки. Перед использованием проверьте ее пробным полетом в редакторе.

## Дроны команд (AI CORE)

Команда описывает свой дрон в `drone.yaml`: размер, масса, тяга и инерционность моторов, винты, батарея, пределы
контроллера, наклон и угол обзора камеры, набор датчиков. Образец с комментариями:
`bench/examples/drones/example_3inch.yaml`; структура файла описана в `bench/schemas/drone.schema.json`.

- Лимиты класса задаете вы: `StreamingAssets/Bench/class_limits.json` (или `-bench-limits`). По умолчанию: не больше
  300 × 300 × 180 мм (предел из задания), от 25 до 1500 г, тяга к весу от 1,5 до 8, до 6 банок и 2200 мА·ч,
  скорость вращения до 1000 °/с, постоянная времени мотора не меньше 10 мс, наклон в Angle до 70°, наклон камеры от 0 до 60°, угол обзора от 60 до 150°, датчики из набора
  `camera, imu, tof, lidar, battery`.
- Команда проверяет свой файл командой `ushqyr-bench validate-drone drone.yaml [--limits class_limits.json]`.
  Симулятор проверяет файл при загрузке теми же правилами и не примет дрон, который их нарушает. Причины написаны
  словами.
- Масса, тяга, инерционность моторов, батарея и пределы берутся из файла как есть. Инерция, сопротивление и
  коэффициенты контроллера считаются из размера и массы: объявить «нефизичный» дрон через них нельзя.
- Дрон летает как коробка объявленного размера, столкновения считаются по шару соответствующего размера. Датчик,
  который не объявлен, не отправляется. SHA-256 файла записывается в каждый результат как `drone_config_hash`.
- Файл это простой YAML: вложенные ключи отступами, числа, текст и списки в одну строку `[a, b, c]`.

Вупер организаторов (класс AI MISSION) пока остается временной моделью: его калибровка ждет измерений.

## Разброс условий

Поле `randomization` в файле правил включает разброс: в каждой попытке сцена меняется по зерну. Одно зерно дает всем
командам одно и то же изменение, и изменение никогда не нарушает проверки трассы.

| | `mild` | `strong` |
|---|---|---|
| Ворота | сдвиг до 10 см, поворот до 3° | 25 см, 8° |
| Стартовая площадка | 15 см, 5° | 30 см, 10° |
| Яркость и цвет света | 0,8 … 1,2, чуть теплее или холоднее | 0,45 … 1,6, заметно теплее или холоднее, другое направление |
| Яркость подсветки ворот | 75 … 100% | 45 … 100% |
| Шум видео | в 0,8 … 1,3 раза | в 0,5 … 2,5 раза |
| Материалы пола и стен | без изменений | один из пяти для каждого |
| Предметы у стен | нет | до 8 цветных ящиков и панелей, часть светится |

В папке попытки лежит трасса в том виде, в каком ее пролетели, поэтому повтор показывает ворота там, где они стояли.

## Датасеты

Команды учат детекторы на размеченных кадрах, которые делает сам симулятор. В приложении: клавиша **T**, затем
**«Датасет»** у нужной трассы (500 кадров в папку результатов). Из командной строки:

```
ushqyr-bench dataset --sim Ushqyr.exe --track H1_Oval --out data/h1 --count 2000 --seed 7 --masks
ushqyr-bench dataset-check data/h1 --draw 100
```

- **Кадры** сняты той же камерой, что и в полете: с объективом, экспозицией и аналоговым видеоканалом. В каждом
  кадре свои сила помех видеоканала, экспозиция и смаз от движения.
- **Положения камеры**: 70% вдоль полета пилота-оракула со случайными смещениями, 30% из случайных мест площадки.
- **Сцена**: разброс `strong` из таблицы выше, меняется каждые 25 кадров, плюс случайные цвета подсветки.
- **Разметка** для каждых ворот в кадре: рамка; четыре угла проема на стороне, обращенной к камере (верхний левый,
  верхний правый, нижний правый, нижний левый, как их видно), с видимостью 0 = за пределами кадра, 1 = закрыт,
  2 = виден; признаки `occluded` и `truncated`; расстояние.
- **Форматы**: YOLO (`images/`, `labels/`, `data.yaml`; рамка и ключевые точки, раскладка «pose») и COCO
  (`annotations/instances_{train,val,test}.json`). Разбиение 80 / 10 / 10 задается зерном.
- **Маски** (`--masks`): PNG на каждый кадр, 0 = не ворота, n = n-е ворота трассы.
- **Проверка разметки**: каждый кадр рисуется второй раз, свет выключен, каждые ворота светятся своим цветом. Рамка
  каждых ворот, которые целиком в кадре, должна совпасть с контуром закрашенных точек с точностью 2 пикселя, а
  каждый видимый угол должен лежать на своих воротах. Счетчики записаны в `dataset.json`; `dataset-check`
  завершается ошибкой, если совпало меньше 98%. Ключ `--draw` пишет кадры с разметкой (и маски рядом с ними) в папку
  `check/`, чтобы посмотреть их глазами.

Режима датасета нет ни в режиме соревнования, ни в серверной сборке.

## Скрытые трассы

Скрытая трасса это обычный файл трассы, который никогда не входит ни во что из выдаваемого.

1. Сделайте ее в редакторе или ключом `-bench-generate` и дайте ей id, который ни о чем не говорит (id попадает в
   результаты).
2. Храните ее в закрытой папке вне проекта, вне всех сборок и наборов.
3. Запускайте ее по пути: `-bench-track D:\private\HID_p_4217.benchtrack.json`. В режиме соревнования API никогда не
   называет трассу; в результатах стоят ее id и хеш, а в папке попытки (только для судей) лежит копия файла.
4. Перед выдачей сборки или набора докажите, что трасс в них нет:

```
ushqyr-bench check-build <папка сборки или набора> --hidden D:\private
```

Команда завершается ошибкой, если какой-то файл там является скрытой трассой или содержит id либо данные ворот скрытой
трассы (в том числе с другими отступами или внутри другого файла). Сжатые архивы не распаковываются: проверяйте
папку до упаковки в zip.

## Набор участника

Набор участника это то, что скачивает команда: симулятор, папка `bench` и эта документация в одном архиве.

1. Соберите симулятор в Unity: **Ushqyr > Build > Build Team Kit (Windows)** или **(Linux)**. В этой сборке есть
   только сцены AI Bench, и она открывает AI Bench без ключа `-bench`; редактор, датасеты и тренировочный режим на месте.
2. Соберите набор:

```
ushqyr-bench make-kit --build Builds/TeamKit/Windows --out Builds/TeamKit/UshqyrAIBench-win-1.4 --server Builds/BenchServer --hidden D:\private
```

`--server` добавляет серверную сборку для Linux: она нужна командам для `build-images` и `submit-check`. С ключом
`--hidden` готовая папка проверяется на скрытые трассы до упаковки, и если трасса найдена, архив не создается. Архив
появляется рядом с папкой. Для каждой платформы делается свой набор.

## Что меняет режим соревнования

- В API нет истинных координат, счета и названия трассы; `RESET` и `PING` отклоняются; симуляция всегда идет в темпе
  реального полета.
- Летать руками не может никто: AI Bench не читает клавиатуру, геймпад и пульт ни в одном режиме.
- Один запуск, одна попытка. У программы есть `connect_timeout` (60 с), чтобы подключиться и дать старт, и
  `step_timeout` (10 с) на каждый шаг; оба считаются в реальном времени.
- Каждая попытка записывается, с видео, если доступен ffmpeg.

## Папка попытки

`<out>/<team>_<track>_a<attempt>_<UTC time>/`

| Файл | Содержимое |
|---|---|
| `result.json` | Очки, время последних засчитанных ворот, статус, команда, id и хеш трассы, зерно, сборка, хеш правил, дрон и хеш его конфигурации, дайджест решения |
| `events.jsonl`, `events.csv` | Старт, каждый пролет ворот (засчитан или нет, с причиной), столкновения, срабатывания failsafe, конец |
| `telemetry.csv` | На каждый шаг: пакет каналов, который отправила программа, признаки арминга и failsafe, показания IMU, ToF и батареи, которые она получила |
| `truth.csv` | **Только для судей.** Истинные координаты, ориентация и скорость на каждом шаге |
| `track.benchtrack.json` | Трасса, которую пролетели |
| `onboard.mp4` | Ровно те кадры, которые получила программа |
| `trackside.mp4` | Неподвижные камеры вокруг площадки, следящие за дроном |
| `judge.mp4` | Вид с трассы с бортовой картинкой в углу, часами, текущим счетом и каждым решением по очкам |
| `replay.grreplay` | Индекс для повтора в приложении |
| `sim.log` | Собственный журнал записи |
| `manifest.json` | SHA-256 и размер каждого файла выше, а также хеши, по которым опознается запуск |
| `manifest.sig` | HMAC-SHA256 файла `manifest.json` с ключом подписи |

Статусы: `finished` (программа сказала, что закончила), `time_limit`, `timeout`, `disconnected`, `stuck` (нет движения
10 с), `invalid` (сбой на нашей стороне или перезапуск тренировочной попытки; не считается).

## Проверка результатов

```
pip install ./bench/runner ./bench/sdk/python

ushqyr-bench verify <папка попытки> --key <файл ключа>
ushqyr-bench leaderboard <папка результатов> --csv results.csv --board leaderboard.csv --semicolon
ushqyr-bench resim <папка попытки>
```

- **verify** печатает `verified`, `checksums_only` (ключ не задан или подписи нет) или `modified` с именем файла,
  который отличается. Правка журнала ломает его контрольную сумму; если переписать манифест под нее, ломается
  подпись.
- **leaderboard**: больше очков выше, затем меньшее время. Строка команды по трассе это ее лучшая засчитанная
  попытка; все трассы складываются, если не задан `--track`.
- **resim** повторяет записанные пакеты каналов с зерном попытки и должен напечатать `same result`. Для него нужен
  симулятор, запущенный в тренировочном режиме на трассе попытки:
  `Ushqyr.exe -bench -bench-track <папка попытки>\track.benchtrack.json`.

В приложении клавиша **Tab** открывает таблицу результатов (эта трасса или все трассы, экспорт CSV, последние
попытки). **«Повтор»** рядом с попыткой открывает повтор для судей: сначала состояние целостности, затем шкала
времени, список решений по очкам (нажмите для перехода) и пять камер (клавиша C: сзади, общий вид, с борта, с
трассы, свободная). Пробел запускает и ставит на паузу; стрелки дают шаг 0,05 с, с Shift 1 с.

## Проверка на утечку

`bench/runner/leak_test.py` доказывает, что координаты нельзя получить через API. Запустите свежий симулятор в режиме
соревнования с ключом `-bench-out`, затем:

```
python bench/runner/leak_test.py --out <папка результатов>
```

Тест шлет враждебные данные по 200 соединениям, летит одну попытку и при этом запрашивает все, чего получать не
должен, пробует запрещенные сообщения, а затем сравнивает каждое полученное число с судейским файлом `truth.csv`
этой попытки. Код возврата 0 значит, что ничего не утекло.

## Решения в Docker

Решение команды это Docker-образ. Симулятор работает во втором контейнере, и у них общая сеть, из которой нет
выхода наружу.

```
ushqyr-bench build-images                       # ushqyr-bench-server (симулятор) и ushqyr-bench-base:cpu
ushqyr-bench submit-check <папка или image.tar> --track H1_Oval --seed 1 --out results [--key key.file] [--logs]
```

Для `build-images` нужна серверная Linux-сборка в `Builds/BenchServer` (меню Unity **Ushqyr / Build / Build Bench
Server (Linux)**). В этой сборке только сцены AI Bench, и она собрана с `USHQYR_BENCH_SERVER`: пилота-оракула,
редактора трасс, инструмента датасетов и сообщения с истинными координатами в ней нет.

**Контейнер симулятора** запускает виртуальный дисплей (Xvfb) и никогда не запускается с `-nographics`: этот ключ
выключил бы камеру. Как он рисует:

| Где | Как | Одна попытка в 120 с (пример решения, H1_Oval) |
|---|---|---|
| Docker Desktop на Windows, `--sim-gpu auto` | Драйвер Direct3D 12 из Mesa на видеокарте компьютера (`--gpus all`, `/usr/lib/wsl` смонтирован только для чтения) | около 4 минут на всю проверку вместе с видео (GTX 1650 Ti) |
| Без видеокарты | Программный OpenGL из Mesa (llvmpipe) | около 40 минут с пресетом Low без видео с трассы; около 3 часов с High |
| Linux-сервер с видеокартой | **еще не настроен и не измерен**: нужна настоящая машина | - |

`-bench-graphics Low|Medium|High|Ultra` задает пресет графики на один запуск, а `-bench-video on|off` заменяет
настройку видео из файла правил. Пресет немного меняет картинку камеры (тени, сглаживание), поэтому на отборе все
команды должны лететь с одним и тем же пресетом. Контейнер пишет папку попытки в
`/results`; файл правил, ключ подписи и папка скрытых трасс монтируются в него только для чтения, если они заданы.

**Контейнер решения** считается враждебным:

| Мера | Ключ Docker |
|---|---|
| Доступен только симулятор; нет интернета, DNS и хоста | `--network <внутренняя сеть>` |
| Файловая система только для чтения, `/tmp` на 256 МБ в памяти | `--read-only --tmpfs /tmp` |
| Нет capabilities, нет повышения привилегий, не root | `--cap-drop ALL --security-opt no-new-privileges --user 10001:10001` |
| Память 4 ГБ (без swap), 4 процессора, 256 процессов | `--memory --memory-swap --cpus --pids-limit` |
| С хоста ничего не смонтировано; разделяемая память только своя (256 МБ) | без `-v`; `--ipc private --shm-size` |

Лимиты это значения по умолчанию из плана (`sandbox.Limits`); настоящие назначают организаторы.

`bench/runner/tests/hostile` это решение, которое пытается выбраться наружу (интернет, DNS, хост, запись в образ,
чтение `/results`, получение прав root, сокет Docker, 400 процессов, другие порты симулятора, запрос истинных
координат). Запустите его командой `submit-check --logs`: в каждой строке должно стоять `blocked`.

### ROS 2

`ushqyr-bench build-images --ros2 jazzy` (или `humble`) собирает базовый образ для решений на ROS 2: ROS 2, SDK,
узел моста и его сообщения. Решение на ROS 2 это обычная заявка: в ее контейнере вместе работают мост и узлы
команды, а симулятор видит одного клиента. Топики, параметры и время описаны в [ros2.md](ros2.md).

## Пакетный прогон

Решение каждой команды на каждой трассе, без участия человека, в один файл результатов.

```
ushqyr-bench batch --submissions submissions.yaml --tracks tracks.yaml --out results
                   [--rules rules.json] [--key key.file] [--workers 2] [--graphics High]
```

`submissions.yaml` (JSON тоже подходит). У каждой команды одно из полей `image`, `archive`, `folder`; пути считаются
от этого файла:

```yaml
- team: Alpha
  image: alpha-solution:latest     # образ, который уже есть в Docker
- team: Beta
  archive: beta.tar                # файл от `docker save`
- team: Gamma
  folder: ./gamma                  # папка с Dockerfile
```

`tracks.yaml`:

```yaml
tracks: [Q1, Q2, Q3]     # id трасс
folder: /srv/hidden      # где лежат Q1.benchtrack.json ...; не указывайте для готовых трасс из сборки
attempts: 2              # на каждую команду и трассу
seed: 1                  # попытка n каждой команды летит с зерном seed + n - 1
```

Папка скрытых трасс монтируется только для чтения и только в контейнер симулятора. Контейнер решения ее никогда не
видит, а в режиме соревнования приветствие не называет трассу.

Что делает прогон:

- Сначала собирает или загружает образ каждой команды и проверяет его размер. О команде без пригодного образа
  сообщается, остальные продолжают.
- Летит трасса за трассой, попытка за попыткой, команда за командой. Каждая команда получает на одной и той же
  трассе одно и то же зерно.
- **Повторяет только сбои инфраструктуры** (ошибки Docker, симулятор не выдал результат): `--retries`, по умолчанию
  2. Решение, которое упало, зависло или не подключилось, не повторяется: симулятор записывает это как результат
  попытки.
- **Его можно остановить и запустить снова.** В `results/batch_state.json` записывается каждое законченное задание;
  та же команда продолжает с того, что осталось.
- `--workers N` летит N попыток одновременно. Они делят процессор и видеокарту, поэтому на небольшой машине больше
  потоков не значит быстрее; в синхронном режиме очки от этого не зависят.

Что он пишет в `--out`:

| Файл | Что это |
|---|---|
| `results.csv` | Каждая попытка: команда, трасса, попытка, очки, время, статус, хеши |
| `results.json` | То же самое, плюс таблица результатов и список проблем (команды без образа, задания, которые не пролетели) |
| `leaderboard.csv` | Место, команда, очки, время: лучшая попытка каждой команды на каждой трассе, сложенные по трассам |
| `attempts/<team>__<track>__aNN/` | Папка попытки (журналы, видео, манифест, подпись) и рядом с ней `solution.log`: то, что напечатало решение |
| `batch_state.json` | Ход прогона, для продолжения |

Код возврата 0, когда у каждого задания есть результат, 1, когда у некоторых его нет, 2, когда прогон не смог
начаться.

Используйте один пресет `--graphics` на весь отбор: пресет меняет картинку камеры.

## Скрытые трассы и ключ подписи на сервере отбора

И то и другое существует только на сервере отбора: не в репозитории, не на машине разработчика, ни в одной сборке и
ни в одном наборе. Сделайте скрытые трассы и ключ там, храните их в папке, которую могут читать только организаторы,
и передавайте пакетному прогону по пути (`folder` в `tracks.yaml`, `--key`). Пока этого сервера нет, разработка идет
на готовых трассах и с одноразовым тестовым ключом.

## Что еще не сделано

- **Linux-сервер с видеокартой** не настроен и не измерен. Контейнер симулятора проверен на Docker Desktop для
  Windows (видеокарта через WSL) и с программной отрисовкой.
- **Единый пресет графики для отбора** не выбран. Пресет меняет картинку камеры, поэтому все команды должны лететь с
  одним и тем же (`--graphics`).
- **Лимиты для решений** (4 ГБ, 4 процессора, образ 8 ГБ, без видеокарты) предварительные, пока организаторы не
  решат.
- **Вупер** (класс AI MISSION) это временная модель, пока он не откалиброван по измерениям реального дрона.
- **Ручного пробного полета нет**: летать руками в AI Bench нельзя вообще. Пробные полеты выполняет пилот-оракул
  или программа.
