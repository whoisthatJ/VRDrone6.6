# Дрон и датчики

Числа на этой странице это значения по умолчанию. Точные значения текущего запуска всегда приходят в приветствии
симулятора: `sim.info` (см. [sdk.md](sdk.md)). Читайте их оттуда, а не зашивайте в код.

## Два класса

| Класс | Дрон | Кто задает |
|---|---|---|
| **AI MISSION** | Вупер организаторов, один для всех | Организаторы |
| **AI CORE** | Свой дрон команды, описанный в `drone.yaml` | Команда, в пределах лимитов класса |

## Вупер (AI MISSION)

| | |
|---|---|
| Размер | 65 мм, 4 мотора, винты в защите |
| Масса | 32 г |
| Батарея | 1S |
| Тяга к весу | около 3 : 1 |
| Газ висения | около 0,56 |
| Радиус столкновения | 4,5 см |

**Модель временная.** Она не откалибрована по реальному дрону организаторов: в приветствии стоит
`drone.calibrated = false`. После калибровки изменятся тяга, инерция и сопротивление, поэтому не подгоняйте решение
под сегодняшние числа слишком точно.

## Управление

Программа шлет каналы пульта, как настоящий передатчик. Команды моторам напрямую недоступны.

| Канал | Что это | Диапазон в SDK |
|---|---|---|
| Roll | крен, + вправо | -1 … 1 |
| Pitch | тангаж, + вперед (нос вниз) | -1 … 1 |
| Throttle | газ | 0 … 1 |
| Yaw | рыскание, + вправо (по часовой стрелке, если смотреть сверху) | -1 … 1 |
| AUX1 | арминг | выкл / вкл |
| AUX2 | режим полета | `angle`, `horizon`, `acro` |

| | |
|---|---|
| Частота шага управления | 100 Гц |
| Задержка канала управления | 10 мс |
| Failsafe | 500 мс без пакетов: моторы отключаются до повторного арминга |

**Режимы полета.** Angle: дрон сам держит горизонт, стик задает угол наклона. Horizon: то же около центра стика, у
краев дрон вращается. Acro: стик задает скорость вращения, горизонт дрон не держит.

**Арминг.** Моторы включаются, только когда AUX1 переходит из «выкл» во «вкл» при газе у нуля.

## Камера

| | |
|---|---|
| Кадр | 640 × 480, RGB, 8 бит на канал |
| Частота | 30 кадров в секунду |
| Угол обзора | 120° по горизонтали, от края до края |
| Наклон | 20° вверх |
| Задержка | 30 мс от съемки до программы |
| Искажение объектива | бочкообразное, `k1 = 0,18` |
| Экспозиция | автоматическая |

**Объектив.** Пусть `x_d = (u - cx) / fx`, `y_d = (v - cy) / fy`, `r² = x_d² + y_d²`. Тогда тангенсы истинных углов:
`x_u = x_d · (1 + k1 · r²)`, `y_u = y_d · (1 + k1 · r²)`. Значения `fx, fy, cx, cy, k1` приходят в приветствии. Пример
расчета: метод `ColorPid._ray` в `color_pid.py`.

**Аналоговый видеоканал.** Картинка проходит модель аналоговой видеосвязи: мягкие детали, размазанный и плывущий
цвет, шум, прыгающие строки и разорванные полосы. Чем дальше дрон от стартовой площадки (там стоит приемник) и чем
больше между ними препятствий, тем хуже картинка. Детектор, обученный на чистых кадрах, на такой картинке ошибается:
учите его на кадрах симулятора ([dataset.md](dataset.md)).

## IMU

| | Гироскоп | Акселерометр |
|---|---|---|
| Частота | 500 Гц | 500 Гц |
| Единицы | рад/с | м/с² |
| Шум (одно отклонение) | 0,004 | 0,08 |
| Постоянное смещение на попытку | 0,003 | 0,04 |
| Предел | 2000 °/с | 16 g |

- Оси корпуса: x вперед, y влево, z вверх.
- Гироскоп: x крен вправо +, y нос вниз +, z поворот влево +.
- Акселерометр меряет кажущееся ускорение: в покое на ровном полу он показывает (0, 0, +9,81).
- От вибрации моторов шум растет: чем выше обороты, тем шумнее оба датчика.
- Ориентации (углов) IMU не дает. Ее нужно считать самим.

За один шаг управления приходит 5 измерений IMU.

## Дальномер ToF

| | |
|---|---|
| Направление | вниз |
| Частота | 50 Гц |
| Диапазон | 0,05 … 4 м |
| Шум | 5 мм + 1% расстояния |

Вне диапазона `valid = false`, а `range = 0`.

## LiDAR

| | |
|---|---|
| Тип | 2D, в горизонтальной плоскости самого дрона |
| Лучей | 360, шаг 1° |
| Частота | 10 оборотов в секунду |
| Диапазон | 0,15 … 12 м |
| Шум | 1 см + 0,5% расстояния; 0,5% лучей пропадает |

Луч `k` смотрит на `k` градусов от оси «вперед», углы растут влево (против часовой стрелки, если смотреть сверху).
Значение 0 значит «ничего не измерено». Лучи одного оборота снимаются по очереди, пока дрон движется, поэтому скан,
снятый в полете, искривлен. Когда дрон наклонен, плоскость скана наклонена вместе с ним и может задевать пол.

## Батарея

Напряжение, 10 раз в секунду. Под нагрузкой напряжение проседает, к концу попытки падает, и вместе с ним падает
тяга.

## Свой дрон (AI CORE)

Опишите дрон в `drone.yaml`: размер, масса, тяга и инерционность моторов, винты, батарея, пределы контроллера,
наклон и угол обзора камеры, набор датчиков. Образец с комментариями: `bench/examples/drones/example_3inch.yaml`.

```
ushqyr-bench validate-drone drone.yaml
Ushqyr.exe -bench -bench-drone drone.yaml
```

Лимиты класса по умолчанию (организаторы могут их изменить):

| Параметр | Предел |
|---|---|
| Размер | не больше 300 × 300 × 180 мм |
| Масса | 25 … 1500 г |
| Тяга к весу | 1,5 … 8 |
| Батарея | до 6 банок, до 2200 мА·ч |
| Постоянная времени мотора | не меньше 10 мс |
| Скорость вращения | до 1000 °/с |
| Угол наклона в Angle | до 70° |
| Наклон камеры | 0 … 60° |
| Угол обзора камеры | 60 … 150° |
| Датчики | из набора `camera, imu, tof, lidar, battery` |

Как это работает:

- Масса, тяга, инерционность моторов, батарея и пределы берутся из файла как есть. Инерция, сопротивление и
  коэффициенты контроллера считаются из размера и массы: объявить «нефизичный» дрон через них нельзя.
- Симулятор проверяет файл при загрузке теми же правилами, что и `validate-drone`, и не примет дрон, который их
  нарушает. Причины написаны словами.
- Датчик, которого нет в списке `sensors`, не отправляется.
- Столкновения считаются по шару, размер которого соответствует объявленному размеру дрона.
- Файл это простой YAML: вложенные ключи отступами, числа, текст и списки в одну строку `[a, b, c]`.
