# Ұйымдастырушыларға арналған нұсқаулық

> Аударма ана тілді маманның тексеруін қажет етеді. Негізгі мәтін: орыс тіліндегі нұсқа.

Жарыс режимінде әрекетті қалай іске қосу керек, симулятор не жазады, оны қалай тексеру керек және бүкіл іріктеуді
адамның қатысуынсыз қалай өткізу керек. Командаларға арналған беттер [README.md](README.md) ішінде тізілген.

## Бір әрекетті іске қосу

```
Ushqyr.exe -bench -bench-mode competition -bench-team "Team name" -bench-attempt 1 ^
           -bench-track H1_Oval -bench-out D:\qualification\results -bench-key D:\secret\bench.key -bench-exit
```

Содан кейін команданың бағдарламасын іске қосыңыз. Бір іске қосу бір әрекет.

| Параметр | Мағынасы |
|---|---|
| `-bench` | Мәзірдің орнына AI Bench-ті ашу |
| `-bench-mode training\|competition` | Әдепкі мән `training` |
| `-bench-track <name or file>` | Ашық трасса атауы бойынша немесе кез келген трасса файлы жолы бойынша (жасырын трассалар осылай қолданылады) |
| `-bench-rules <file>` | Ережелер файлы; жоқ өрістер `StreamingAssets/Bench/rules.json` файлындағы әдепкі мәндерде қалады |
| `-bench-team`, `-bench-attempt`, `-bench-solution <digest>` | Нәтижеге жазылады |
| `-bench-out <folder>` | Әрекет бумалары қайда жазылады. Онсыз: пайдаланушы деректері бумасындағы `BenchResults`. Жаттығу режимінде әрекеттер тек осы параметр берілгенде жазылады |
| `-bench-key <file>` | Қол қою кілті (кез келген мазмұндағы кемінде 16 байт). Сондай-ақ `USHQYR_BENCH_KEY_FILE`. Онсыз әрекеттерде бақылау сомалары болады, бірақ қолтаңба болмайды |
| `-bench-ffmpeg <file>` | Бейнелерге арналған ffmpeg. Сондай-ақ `USHQYR_FFMPEG`, `StreamingAssets/Bench/ffmpeg.exe` немесе PATH. ffmpeg болмаса, әрекет бейнесіз жазылады |
| `-bench-seed <n>`, `-bench-port <n>`, `-bench-token <text>` | Шу тұқымы (seed), API порты, бағдарлама көрсетуге тиіс токен |
| `-bench-listen-all` | Бағдарламаны басқа машинадан немесе контейнерден қабылдау (әдепкі бойынша: тек осы компьютер) |
| `-bench-exit` | Әрекет аяқталып, оның файлдары жазылған соң шығу |
| `-bench-replay <attempt folder>` | Әрекеттің төрешілерге арналған қайта көруін ашу |
| `-bench-edit <name or file>` | Трасса редакторын трассамен ашу |
| `-bench-generate <venue> <seed> <difficulty> <file>` | Кездейсоқ трассаны файлға жазып, шығу (алаң `hall` немесе `parking`, күрделілік 1-ден 3-ке дейін) |
| `-bench-drone <drone.yaml>` | Вупердің орнына команданың өз дронымен ұшу (AI CORE класы) |
| `-bench-limits <class_limits.json>` | AI CORE класының шектері (әдепкі бойынша: трассалардың қасындағы файл) |
| `-bench-dataset <folder>` | Әрекетті іске қосудың орнына белгіленген датасет жасау; `-bench-dataset-count`, `-bench-dataset-seed`, `-bench-dataset-profile`, `-bench-dataset-masks` параметрлерімен бірге. Тек жаттығу режимі |

Редакторда дәл осы параметрлер `UserSettings/bench-args.txt` файлынан оқылады, әр жолда бір параметр немесе мән.

## Ережелер файлы

Ұйымдастырушылар өзгерткісі келуі мүмкін нәрсенің бәрі жинақта емес, ережелер файлында (`-bench-rules`) тұрады. Өрістер
мен олардың әдепкі мәндері `StreamingAssets/Bench/rules.json` файлында. Ең жиі өзгертілетіндері:

| Өріс | Әдепкі мән | Мағынасы |
|---|---|---|
| `time_mode` | `sync` | `sync`: бір командаға бір қадам, қайталанады. `realtime`: симулятор нақты сағат бойынша жүреді |
| `rc_latency_ms`, `rc_jitter_ms`, `rc_loss_percent` | 10, 0, 0 | Байланыс кідірісі, әр пакетте өзгеріп тұратын қосымша кідіріс, жоғалған пакеттердің үлесі |
| `compute_delay_ms` | 0 | Бағдарламаның есептеу уақытын білдіретін тұрақты кідіріс. Сонда синхронды режимде баяу және жылдам компьютерлер бірдей ұшады |
| `camera_distortion` | 0.18 | Объективтің бөшке тәрізді бұрмалануы (`k1`); 0 = жоқ |
| `camera_auto_exposure` | true | |
| `video_range` | 80 | Аналогтық бейне ең нашар болатын қашықтық, метрмен |
| `lidar`, `lidar_hz` | true, 10 | |
| `randomization` | `none` | `mild` немесе `strong`: әр әрекет сахнаны өз тұқымы бойынша өзгертеді («Жағдайларды өзгерту» бөлімін қараңыз) |

## Трассалар және алаңдар

Екі алаң бар: **зал** (40 × 20 × 8 м) және **паркинг** (60 × 34 м, таза биіктігі 3,4 м, 28 бағанадан тұратын тор, ұзын
қабырғалардың бойында тұрған көліктер). Әрқайсысында жарық нұсқалары бар (зал: әдепкі, күңгірт, жылы; паркинг: әдепкі,
күңгірт, жарық). Нұсқаны трасса файлы таңдайды.

`StreamingAssets/Bench/Tracks` ішінде алты ашық трасса жеткізіледі:

| Трасса | Алаң | Қақпа саны | Идеясы |
|---|---|---|---|
| `H1_Oval` | зал | 6 | Жазық сопақша; келесі қақпа әрқашан көрініп тұрады |
| `H2_Eight` | зал | 8 | Қиылысы бар сегіздік |
| `H3_Slalom` | зал | 7 | Ығысуы бар слалом және 180° күрт бұрылыс |
| `X1_Mixed` | зал | 10 | Жарықтандырудың (LED) бес түсі, сол түстерге боялған және жарқырайтын панельдермен бірге |
| `P1_Columns` | паркинг | 6 | Бағана қатарларын айналатын ілмек, жарық әлсіз |
| `P2_Maze` | паркинг | 9 | Бағаналардың артындағы бұрылыстар: келесі қақпа жиі көрінбейді |

`Docs/bench/track_check.md` файлында олардың әрқайсысы тексеруден өтетіні және оракул-пилот толық айналым жасайтыны
жазылған.

**Трасса редакторы.** Қолданбада: **T** трассалар тізімін ашады (ұшу, өңдеу, жаңа трасса). Редакторда қақпаларды алаң
жоспары бойынша сүйреңіз, әрқайсысына жарықтандыру (LED) түсін, жарықтығын, тұрақты жану немесе жыпылықтау режимін және
рұқсат етілген бағытты беріңіз; старт алаңын жылжытыңыз және бұрыңыз; жарық пен уақыт шегін таңдаңыз. Тексерулер өңдеу
кезінде жүреді: қайталау ережесіне жеткілікті қақпа саны, қабырғаларға, бағаналарға және көліктерге дейінгі саңылау,
ұшып өтуге орын, қақпалар арасындағы қашықтық, старттан көрінетін қақпа. **«Сынақ ұшуы (оракул-пилот)»** оракул-пилотқа
трассаны ұшып өтуге мүмкіндік береді және оның жолын сызады. **«Сақтау»** файлды пайдаланушының `BenchTracks` бумасына
жазады; **«Карта экспорты»** қасына жоғарыдан түсірілген суретті жазады; **«Ұшып көру»** трассаны бағдарлама үшін ашады.

**Оракул-пилот.** Шынайы координаталарды білетін автопилот. Ол тек трасса жасауға арналған (сынақ ұшулары, трассаларды
тексеру, датасеттегі камера жолдары), сервер жинағына компиляцияланбайды және API-мен ешқандай байланысы жоқ.

**Кездейсоқ трассалар.** Редактордағы «Кездейсоқ трасса» (тұқым, 1-ден 3-ке дейінгі деңгей) немесе командалық жолдан:
`Ushqyr.exe -bench-generate parking 4217 3 D:\private\HID_p_4217.benchtrack.json`. Бір тұқым бір трассаны береді, және
әрбір жасалған трасса тексерулерден өтеді. Қолданар алдында оны редакторда сынақ ұшуымен тексеріңіз.

## Команда дрондары (AI CORE)

Команда өз дронын `drone.yaml` файлында сипаттайды: өлшемі, массасы, моторлардың тартуы мен инерттілігі, винттер,
батарея, контроллер шектері, камераның еңкеюі мен көру бұрышы және қандай датчиктері бар екені. Түсініктемелері бар
мысал: `bench/examples/drones/example_3inch.yaml`; файлдың құрылымы `bench/schemas/drone.schema.json` ішінде.

- Класс шектерін өзіңіз белгілейсіз: `StreamingAssets/Bench/class_limits.json` (немесе `-bench-limits`). Әдепкі мәндер:
  ең көбі 300 × 300 × 180 мм (тапсырманың шегі), 25-тен 1500 г-ға дейін, тартудың салмаққа қатынасы 1,5-тен 8-ге дейін,
  6 банкаға дейін және 2200 мА·сағ-қа дейін, айналу жылдамдығы 1000 °/с-қа дейін, мотордың уақыт тұрақтысы 10 мс-тен кем емес, Angle режиміндегі еңкею бұрышы 70°-қа дейін, камераның еңкеюі 0-ден 60°-қа дейін,
  көру бұрышы 60-тан 150°-қа дейін, датчиктер `camera, imu, tof, lidar, battery` жиынынан.
- Команда өз файлын `ushqyr-bench validate-drone drone.yaml [--limits class_limits.json]` командасымен тексереді.
  Симулятор файлды жүктегенде дәл сол тексерулерді жүргізеді және олардан өтпеген дронды қабылдамайды. Себептері
  қарапайым сөзбен жазылады.
- Масса, тарту, мотор инерттілігі, батарея және шектер файлда қалай көрсетілсе, солай алынады. Инерция, кедергі және
  контроллер коэффициенттері өлшем мен массадан есептеледі, сондықтан команда олар арқылы өзіне «физикаға сыймайтын»
  дрон жариялай алмайды.
- Дрон жарияланған өлшемдегі қорап ретінде ұшады, соқтығысу шары соған сәйкес келеді. Жарияланбаған датчик
  жіберілмейді. Файлдың SHA-256 мәні әр нәтиженің `drone_config_hash` өрісіне жазылады.
- Файл қарапайым YAML: шегініспен берілген кірістірілген кілттер, сандар, мәтін және бір жолдағы тізімдер `[a, b, c]`.

Ұйымдастырушылардың вупері (AI MISSION класы) әзірге уақытша модель; оны калибрлеу өлшемдерді күтіп тұр.

## Жағдайларды өзгерту

Ережелер файлындағы `randomization` әр әрекетте сахнаны оның тұқымы бойынша өзгертеді. Бір тұқым әр командаға бірдей
өзгеріс береді, және өзгеріс трассаның тексерулерін ешқашан бұзбайды.

| | `mild` | `strong` |
|---|---|---|
| Қақпалар | 10 см-ге дейін жылжу, 3°-қа дейін бұрылу | 25 см, 8° |
| Старт алаңы | 15 см, 5° | 30 см, 10° |
| Жарық деңгейі мен түсі | 0,8-ден 1,2-ге дейін, сәл жылы немесе суық | 0,45-тен 1,6-ға дейін, айтарлықтай жылы немесе суық, бағыты өзгерген |
| Жарықтандыру (LED) жарықтығы | 75-тен 100%-ға дейін | 45-тен 100%-ға дейін |
| Бейне шуы | 0,8-ден 1,3 есеге дейін | 0,5-тен 2,5 есеге дейін |
| Еден мен қабырға материалдары | өзгеріссіз | әрқайсысы үшін бесеудің бірі |
| Қабырға бойындағы заттар | жоқ | 8-ге дейін түрлі түсті жәшік пен панель, кейбірі жарқырайды |

Әрекет бумасында трасса ұшу кезіндегі күйінде сақталады, сондықтан қайта көруде қақпалар өз тұрған жерінде көрінеді.

## Датасеттер

Командалар детекторларды симулятордың өзі жасаған белгіленген кадрларда оқытады. Қолданбада: **T**, содан кейін
трассаның жанындағы **«Датасет»** (нәтижелер бумасына 500 кадр). Командалық жолдан:

```
ushqyr-bench dataset --sim Ushqyr.exe --track H1_Oval --out data/h1 --count 2000 --seed 7 --masks
ushqyr-bench dataset-check data/h1 --draw 100
```

- **Кадрлар** ұшу кезіндегі камерадан өтеді: объектив, экспозиция және аналогтық байланыс. Байланыс әсерлерінің күші,
  экспозиция және қозғалыстан болатын бұлдырлау әр кадрда өзгереді.
- **Камера орындары**: 70%-ы оракул-пилоттың ұшу жолының бойында кездейсоқ ығысулармен, 30%-ы алаңның кез келген жерінде.
- **Сахна**: жоғарыдағы `strong` деңгейіндегі жағдайларды өзгерту, әр 25 кадр сайын жаңартылады, оған қоса кездейсоқ
  жарықтандыру (LED) түстері.
- **Белгілеу** кадрдағы әр қақпа үшін: жақтау; камераға қараған жағындағы қақпа ойығының төрт бұрышы (көрінуі бойынша
  жоғарғы сол, жоғарғы оң, төменгі оң, төменгі сол), көрінуі 0 = кескіннен тыс, 1 = жасырылған, 2 = көрінеді;
  `occluded` және `truncated` жалаушалары; қашықтық.
- **Форматтар**: YOLO (`images/`, `labels/`, `data.yaml`; жақтау және түйінді нүктелер, «pose» орналасуы) және COCO
  (`annotations/instances_{train,val,test}.json`). 80 / 10 / 10 бөлінуі тұқымнан алынады.
- **Маскалар** (`--masks`): әр кадрға бір PNG, 0 = қақпа жоқ, n = трассаның n-ші қақпасы.
- **Белгілеуді тексеру**: әр кадр екінші рет салынады, жарық өшірілген және әр қақпа өз түсімен жарқырайды. Кадрға
  толық сыйған әр қақпаның жақтауы оның боялған пиксельдерінің контурымен 2 пиксель дәлдікпен сәйкес келуі керек, ал
  әрбір көрінетін бұрыш өз қақпасының үстінде жатуы керек. Есептегіштер `dataset.json` ішінде; 98%-дан төмен болса,
  `dataset-check` қатемен аяқталады. `--draw` көзбен қарап шығу үшін белгіленген суреттерді (және қасына маскаларды)
  `check/` бумасына жазады.

Датасет режимі жарыс режимінде де, сервер жинағында да жоқ.

## Жасырын трассалар

Жасырын трасса дегеніміз таратылатын ешбір нәрсенің құрамына ешқашан кірмейтін кәдімгі трасса файлы.

1. Оны редакторда немесе `-bench-generate` арқылы жасаңыз және оған ештеңе айтпайтын id беріңіз (id нәтижелерге түседі).
2. Оны жобадан тыс және әрбір жинақ пен қатысушы жинағынан тыс жабық бумада сақтаңыз.
3. Онымен жол бойынша ұшыңыз: `-bench-track D:\private\HID_p_4217.benchtrack.json`. Жарыс режимінде API трассаны ешқашан
   атамайды; нәтижелерде оның id мен хеші болады, ал әрекет бумасында (тек төрешілер үшін) файлдың көшірмесі болады.
4. Жинақты немесе қатысушы жинағын таратар алдында трассалардың оның ішінде жоқ екенін дәлелдеңіз:

```
ushqyr-bench check-build <build or kit folder> --hidden D:\private
```

Егер ондағы қандай да бір файл жасырын трасса болса немесе ішінде жасырын трассаның id мәні не қақпа деректері болса
(шегіністері өзгертілген немесе басқа файлдың ішінде болса да), команда қатемен аяқталады. Сығылған архивтер ашылмайды:
буманы zip-ке салмас бұрын тексеріңіз.

## Қатысушы жинағы

Қатысушы жинағы дегеніміз команда жүктеп алатын нәрсе: симулятор, `bench` бумасы және осы құжаттама бір архивте.

1. Симуляторды Unity-де жинаңыз: **Ushqyr > Build > Build Team Kit (Windows)** немесе **(Linux)**. Бұл жинақта тек
   AI Bench сахналары бар және ол AI Bench режимін `-bench` кілтінсіз ашады; редактор, датасеттер және жаттығу режимі орнында.
2. Жинақты құрастырыңыз:

```
ushqyr-bench make-kit --build Builds/TeamKit/Windows --out Builds/TeamKit/UshqyrAIBench-win-1.4 --server Builds/BenchServer --hidden D:\private
```

`--server` Linux-қа арналған серверлік жинақты қосады: ол командаларға `build-images` және `submit-check` үшін қажет.
`--hidden` кілтімен дайын бума архивтелмес бұрын жасырын трассаларға тексеріледі, ал трасса табылса, архив жасалмайды.
Архив буманың қасында пайда болады. Әр платформаға жеке жинақ жасалады.

## Жарыс режимі нені өзгертеді

- API-де шынайы координаталар да, есеп те, трасса атауы да жоқ; `RESET` және `PING` қабылданбайды; симуляция әрқашан
  нақты ұшу қарқынымен жүреді.
- Ешкім қолмен ұша алмайды: AI Bench екі режимде де пернетақтаны, геймпадты және пультті оқымайды.
- Бір іске қосуға бір әрекет. Бағдарламаның қосылып, старт беруіне `connect_timeout` (60 с), ал әр қадамға
  `step_timeout` (10 с) беріледі, екеуі де нақты уақытпен.
- Әр әрекет жазылады, ffmpeg қолжетімді болса, бейнесімен бірге.

## Әрекет бумасы

`<out>/<team>_<track>_a<attempt>_<UTC time>/`

| Файл | Мазмұны |
|---|---|
| `result.json` | Ұпайлар, ұпай берген соңғы қақпаның уақыты, статус, команда, трасса id мен хеші, тұқым, жинақ, ережелер хеші, дрон және оның конфигурация хеші, шешім дайджесті |
| `events.jsonl`, `events.csv` | Старт, әрбір қақпадан ұшып өту (ұпай берілген немесе берілмеген, себебімен), соқтығысулар, failsafe жағдайлары, соңы |
| `telemetry.csv` | Әр қадам бойынша: бағдарлама жіберген RC пакеті, арминг және failsafe жалаушалары, оған берілген IMU, ToF және батарея көрсеткіштері |
| `truth.csv` | **Тек төрешілер үшін.** Әр қадамдағы шынайы орын, бағдар және жылдамдық |
| `track.benchtrack.json` | Ұшып өткен трасса |
| `onboard.mp4` | Дәл бағдарлама алған кадрлар |
| `trackside.mp4` | Алаң айналасындағы, дронның соңынан еретін тұрақты камералар |
| `judge.mp4` | Трасса жанынан түсірілген бейне, бұрышында борттық кескін, сағат, ағымдағы есеп және ұпай бойынша әр шешім |
| `replay.grreplay` | Қолданба ішіндегі қайта көруге арналған индекс |
| `sim.log` | Жазу құралының өз журналы |
| `manifest.json` | Жоғарыдағы әр файлдың SHA-256 мәні мен өлшемі, оған қоса іске қосуды анықтайтын хештер |
| `manifest.sig` | `manifest.json` файлының қол қою кілтімен жасалған HMAC-SHA256 мәні |

Статустар: `finished` (бағдарлама жұмысын бітіргенін айтты), `time_limit`, `timeout`, `disconnected`, `stuck` (10 с бойы
қозғалыс жоқ), `invalid` (біздің тарапта іркіліс болды немесе жаттығу әрекеті қайта басталды; есепке алынбайды).

## Нәтижелерді тексеру

```
pip install ./bench/runner ./bench/sdk/python

ushqyr-bench verify <attempt folder> --key <key file>
ushqyr-bench leaderboard <results folder> --csv results.csv --board leaderboard.csv --semicolon
ushqyr-bench resim <attempt folder>
```

- **verify** мынаны басып шығарады: `verified`, `checksums_only` (кілт берілмеген немесе қол қойылмаған) немесе `modified`
  және өзгеше файлдың атауы. Журналды өңдеу оның бақылау сомасын бұзады; манифестті соған сәйкестендіріп қайта жазу
  қолтаңбаны бұзады.
- **leaderboard**: алдымен ұпайы көп, содан кейін уақыты аз команда. Команданың трасса бойынша жолы оның есепке алынған
  ең үздік әрекеті; `--track` берілмесе, барлық трасса қосылады.
- **resim** жазылған RC пакеттерін әрекеттің тұқымымен қайта ойнатады және `same result` деп басып шығаруы керек. Оған
  әрекеттің трассасында жаттығу режимінде іске қосылған симулятор қажет:
  `Ushqyr.exe -bench -bench-track <attempt folder>\track.benchtrack.json`.

Қолданбада **Tab** нәтижелер кестесін ашады (осы трасса немесе барлық трасса, CSV экспорты, соңғы әрекеттер). Әрекеттің
жанындағы **«Қайта көру»** төрешілерге арналған қайта көруді ашады: алдымен тұтастық күйі, содан кейін уақыт шкаласы,
ұпай бойынша шешімдер тізімі (өту үшін басыңыз) және бес камера (C пернесі: артынан, жалпы көрініс, борттан, трасса
жанынан, еркін). Бос орын пернесі ойнатады және кідіртеді; бағыттауыш пернелер 0,05 с-қа, Shift-пен 1 с-қа жылжытады.

## Ақпарат жылыстауын тексеру

`bench/runner/leak_test.py` координаталарды API арқылы алу мүмкін емес екенін дәлелдейді. Жаңа симуляторды жарыс
режимінде `-bench-out` параметрімен іске қосыңыз, содан кейін:

```
python bench/runner/leak_test.py --out <results folder>
```

Ол 200 қосылым арқылы зиянды кіріс деректерін жібереді, алуға тиіс емес нәрсенің бәрін сұрай отырып бір әрекет ұшады,
тыйым салынған хабарларды байқап көреді, содан кейін алған әрбір санды сол әрекеттің төрешілерге арналған `truth.csv`
файлымен салыстырады. Шығу коды 0 ештеңе жылыстамағанын білдіреді.

## Docker ішіндегі шешімдер

Команданың шешімі дегеніміз Docker-образ. Симулятор екінші контейнерде жұмыс істейді, және екеуі сыртқа шығар жолы жоқ
ортақ желіні пайдаланады.

```
ushqyr-bench build-images                       # ushqyr-bench-server (симулятор) және ushqyr-bench-base:cpu
ushqyr-bench submit-check <folder or image.tar> --track H1_Oval --seed 1 --out results [--key key.file] [--logs]
```

`build-images` командасына `Builds/BenchServer` ішіндегі Linux сервер жинағы қажет (Unity мәзірі **Ushqyr / Build /
Build Bench Server (Linux)**). Бұл жинақта тек AI Bench сахналары бар және ол `USHQYR_BENCH_SERVER` белгісімен
компиляцияланған: оракул-пилот, трасса редакторы, датасет құралы және шынайы координаталар хабары онда жоқ.

**Симулятор контейнері** виртуалды дисплейді (Xvfb) іске қосады және ешқашан `-nographics` кілтімен іске қосылмайды,
өйткені ол камераны өшіріп тастар еді. Ол суретті қалай салады:

| Қайда | Қалай | 120 с бір әрекет (мысал шешім, H1_Oval) |
|---|---|---|
| Windows-тағы Docker Desktop, `--sim-gpu auto` | Компьютердің бейнекартасындағы Mesa-ның Direct3D 12 драйвері (`--gpus all`, `/usr/lib/wsl` тек оқуға қосылған) | бейнелерді қосқанда бүкіл тексеруге шамамен 4 минут (GTX 1650 Ti) |
| GPU жоқ | Mesa-ның бағдарламалық OpenGL-і (llvmpipe) | Low пресетінде трасса жанынан түсірілетін бейнесіз шамамен 40 минут; High пресетінде шамамен 3 сағат |
| GPU бар Linux сервері | **әлі бапталмаған және өлшенбеген**: нақты машина қажет | - |

`-bench-graphics Low|Medium|High|Ultra` бір іске қосуға пресетті белгілейді, ал `-bench-video on|off` ережелер файлындағы
бейне баптауын алмастырады. Пресет камера кескінін аздап өзгертеді (көлеңкелер, тегістеу), сондықтан іріктеуде әр
команда бірдей пресетпен іске қосылуы керек. Контейнер әрекет бумасын `/results` ішіне жазады; ережелер файлы, қол қою
кілті және жасырын трассалар бумасы берілген болса, оған тек оқуға қосылады.

**Шешім контейнері** дұшпан ретінде қарастырылады:

| Шара | Docker параметрі |
|---|---|
| Тек симулятор қолжетімді; интернет те, DNS те, хост та жоқ | `--network <internal network>` |
| Файлдық жүйе тек оқуға арналған, жадта 256 МБ `/tmp` | `--read-only --tmpfs /tmp` |
| Capabilities жоқ, артықшылықты арттыру жоқ, root емес | `--cap-drop ALL --security-opt no-new-privileges --user 10001:10001` |
| Жад 4 ГБ (swap жоқ), 4 процессор, 256 процесс | `--memory --memory-swap --cpus --pids-limit` |
| Хосттан ештеңе қосылмаған; тек өзінің ортақ жады (256 МБ) | `-v` жоқ; `--ipc private --shm-size` |

Бұл шектер жоспардағы әдепкі мәндер (`sandbox.Limits`); нақты шектерді ұйымдастырушылар шешеді.

`bench/runner/tests/hostile` дегеніміз сыртқа шығуға тырысатын шешім (интернет, DNS, хост, образға жазу, `/results`
оқу, root болу, Docker сокеті, 400 процесс, симулятордың басқа порттары, шынайы координаталарды сұрау). Оны
`submit-check --logs` арқылы іске қосыңыз: әр жолда `blocked` деп жазылуы керек.

### ROS 2

`ushqyr-bench build-images --ros2 jazzy` (немесе `humble`) ROS 2 шешімдеріне арналған базалық образды жинайды: ROS 2, SDK,
көпір түйіні және оның хабарлары. ROS 2 шешімі кәдімгі жіберілім: оның контейнері көпір мен команда түйіндерін бірге
іске қосады, ал симулятор бір клиентті көреді. Топиктер, параметрлер және уақыт [ros2.md](ros2.md) ішінде.

## Пакеттік іске қосу

Әр команданың шешімі әр трассада, адамның қатысуынсыз, бір нәтижелер файлына.

```
ushqyr-bench batch --submissions submissions.yaml --tracks tracks.yaml --out results
                   [--rules rules.json] [--key key.file] [--workers 2] [--graphics High]
```

`submissions.yaml` (JSON да жарайды). Әр командаға `image`, `archive`, `folder` кілттерінің бірі; жолдар осы файлға
қатысты беріледі:

```yaml
- team: Alpha
  image: alpha-solution:latest     # Docker ішінде бұрыннан бар образ
- team: Beta
  archive: beta.tar                # `docker save` файлы
- team: Gamma
  folder: ./gamma                  # Dockerfile бар бума
```

`tracks.yaml`:

```yaml
tracks: [Q1, Q2, Q3]     # id мәндері
folder: /srv/hidden      # Q1.benchtrack.json ... жатқан жер; жинақтағы ашық трассалар үшін жазбаңыз
attempts: 2              # әр команда мен трассаға
seed: 1                  # әр команданың n-ші әрекеті seed + n - 1 тұқымымен ұшады
```

Жасырын трассалар бумасы тек симулятор контейнеріне ғана, тек оқуға қосылады. Шешім контейнері оны ешқашан көрмейді,
және жарыс режимінде сәлемдесу хабары трассаны атамайды.

Іске қосу не істейді:

- Алдымен әр команданың образын жинайды немесе жүктейді және оның өлшемін тексереді. Жарамды образы жоқ команда туралы
  хабарланады, ал қалғандары жалғастырады.
- Трассадан трассаға, әрекеттен әрекетке, командадан командаға ұшады. Әр команда бір трассада бірдей тұқымға кезігеді.
- **Тек инфрақұрылым іркілістерінде ғана қайталайды** (Docker қателері, симулятордың нәтиже бермеуі): `--retries`,
  әдепкі мән 2. Құлаған, қатып қалған немесе мүлде қосылмаған шешім қайталанбайды: симулятор мұны әрекеттің нәтижесі
  ретінде жазады.
- **Тоқтатып, қайта бастауға болады.** `results/batch_state.json` әрбір аяқталған тапсырманы жазып отырады; сол команда
  қалғанын жалғастырады.
- `--workers N` бір уақытта N әрекет ұшады. Олар процессор мен бейнекартаны бөліседі, сондықтан шағын машинада
  жұмысшылардың көп болуы жылдамдықтың артуын білдірмейді; синхронды режимде ұпайлар бұған тәуелді емес.

`--out` ішіне не жазады:

| Файл | Бұл не |
|---|---|
| `results.csv` | Әр әрекет: команда, трасса, әрекет, ұпайлар, уақыт, статус, хештер |
| `results.json` | Дәл сол, оған қоса нәтижелер кестесі және мәселелер тізімі (образы жоқ командалар, ұшпаған тапсырмалар) |
| `leaderboard.csv` | Орын, команда, ұпайлар, уақыт: әр команданың әр трассадағы ең үздік әрекеті, трассалар бойынша қосылған |
| `attempts/<team>__<track>__aNN/` | Әрекет бумасы (логтар, бейнелер, манифест, қолтаңба) және оның қасында `solution.log`: шешім басып шығарған мәтін |
| `batch_state.json` | Жалғастыруға арналған орындалу барысы |

Әр тапсырманың нәтижесі болса, шығу коды 0; кейбірінде болмаса, 1; іске қосу басталмай қалса, 2.

Бүкіл іріктеуге бір `--graphics` пресетін қолданыңыз: пресет камера кескінін өзгертеді.

## Іріктеу серверіндегі жасырын трассалар және қол қою кілті

Екеуі де тек іріктеу серверінде болады: репозиторийде де, әзірлеушінің машинасында да, ешбір жинақта немесе қатысушы
жинағында да жоқ. Жасырын трассалар мен кілтті сол жерде жасаңыз, оларды тек ұйымдастырушылар оқи алатын бумада
сақтаңыз және пакеттік іске қосуға жол бойынша беріңіз (`tracks.yaml` ішіндегі `folder`, `--key`). Ол сервер пайда
болғанша әзірлеу кезінде ашық трассалар және бір реттік сынақ кілті қолданылады.

## Әлі жасалмаған

- **Бейнекартасы бар Linux сервері** бапталмаған және өлшенбеген. Симулятор контейнері Windows-қа арналған Docker
  Desktop-та (WSL арқылы бейнекарта) және бағдарламалық сурет салумен тексерілген.
- **Іріктеуге арналған бір графика пресеті** таңдалмаған. Пресет камера кескінін өзгертеді, сондықтан әр команда бірдей
  пресетпен ұшуы керек (`--graphics`).
- **Шешімдерге арналған шектер** (4 ГБ, 4 процессор, 8 ГБ образ, бейнекарта жоқ) ұйымдастырушылар шешкенше уақытша мәндер.
- **Вупер** (AI MISSION класы) нақты дронның өлшемдері бойынша калибрленгенше уақытша модель.
- **Қолмен сынақ ұшуы жоқ**: AI Bench-те қолмен ұшу мүлде жоқ. Сынақ ұшуларын оракул-пилот немесе бағдарлама жасайды.
