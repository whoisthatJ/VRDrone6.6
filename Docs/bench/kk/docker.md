# Docker ішіндегі шешім

> Аударма ана тілді маманның тексеруін қажет етеді. Негізгі мәтін: орыс тіліндегі нұсқа.

Іріктеуде сіздің шешіміңіз Docker-образ ретінде іске қосылады. Бұл бетте образды қалай жинау керегі және оны өз
компьютеріңізде сервердегідей жағдайда қалай тексеру керегі көрсетілген.

## Не қажет

- Docker (Windows-та: WSL2 бар Docker Desktop).
- Қатысушы жинағынан: `bench/template`, `bench/runner`, `bench/docker` бумалары және симулятордың Linux жинағы `Builds/BenchServer`.
- `ushqyr-bench-server` симулятор образы және `ushqyr-bench-base:cpu` базалық образы. Оларды бір команда жинайды (төменде қараңыз).

```
pip install ./bench/runner
ushqyr-bench build-images
```

`build-images` симулятордың Linux-жинағын `Builds/BenchServer` бумасынан алады. Командаларға ол қатысушы жинағымен бірге
дайын күйінде беріледі; ұйымдастырушылар оны Unity-де жинайды: **Ushqyr / Build / Build Bench Server (Linux)** мәзірі.

## Үлгі

`bench/template` бумасын көшіріп алыңыз және өз кодыңызды `solution.py` файлына жазыңыз.

| Файл | Бұл не |
|---|---|
| `Dockerfile` | Образ қалай жиналады. Негізі: `ushqyr-bench-base:cpu` (Python 3.11, SDK, NumPy, OpenCV) |
| `solution.py` | Сіздің шешіміңіз. Үлгіде дрон көтеріліп, орнында қалқып тұрады |
| `requirements.txt` | Қосымша Python пакеттері |

Симулятордың мекенжайы мен токені `USHQYR_BENCH_HOST`, `USHQYR_BENCH_PORT`, `USHQYR_BENCH_TOKEN` орта айнымалыларында
келеді. `Sim.connect()` оларды өзі оқиды. Әрекет аяқталғанда бағдарлама өзі жұмысын аяқтауы керек.

## Тексеру

```
ushqyr-bench submit-check ./my_solution --track H1_Oval --logs
```

Команда образды жинайды, симуляторды жарыс режимінде және оның қасында сіздің шешіміңізді іске қосады, әрекеттің соңын
күтеді және нәтижені басып шығарады. Әрекет бумасы (логтар, бейне, бақылау сомалары) `bench_results` ішінде пайда болады.

Дайын мысал: `ushqyr-bench submit-check bench/examples/color_pid`.

## Контейнердегі жағдайлар

Шешім жабық контейнерде жұмыс істейді. Мұны алдын ала ескеріңіз.

| Жағдай | Мәні |
|---|---|
| Желі | Тек симулятор. Интернет пен DNS жоқ: барлық пакеттер мен модель салмақтары образдың ішінде болуы керек |
| Файлдар | Файлдық жүйе тек оқуға арналған. `/tmp` ішіне жазуға болады (256 МБ, жадта) |
| Пайдаланушы | root емес (uid 10001), артықшылықтарсыз |
| Жад | 4 ГБ |
| Процессор | 4 ядро |
| Процестер | 256-дан көп емес |
| Образ өлшемі | 8 ГБ-тан көп емес |
| Бейнекарта | жоқ (әдепкі бойынша) |

Кестедегі сандар алдын ала берілген: түпкілікті шектерді ұйымдастырушылар белгілейді.

## Уақыт

| Қайда іске қосылған | 120 с әрекетті тексеру қанша уақыт алады |
|---|---|
| Бейнекартасы бар Windows-тағы Docker Desktop (GTX 1650 Ti-де тексерілген) | образды жинау мен бейне жазуды қосқанда шамамен 4 минут |
| Бейнекартасыз (бағдарламалық сурет салу) | 8 ядрода шамамен 40 минут |

Windows-та `submit-check` бейнекартаны симулятор контейнеріне өзі қосады (`--sim-gpu auto` кілті). Бейнекартасыз
симулятор суретті бағдарламалық түрде салады: команда ең қарапайым графиканы қосады және трасса жанынан түсірілетін
бейнені жазбайды, әйтпесе әрекет сағаттап жүрер еді.

Жылдамдық нәтижеге әсер етпейді: синхронды режимде әрекет уақыты симулятор сағаты бойынша есептеледі, және симулятор әр
қадамда сіздің командаңызды күтеді.

## Жиі кездесетін қателер

| Хабар | Себебі |
|---|---|
| `the Docker engine is not running` | Docker Desktop-ты іске қосыңыз |
| `the base image ... is not built yet` | `ushqyr-bench build-images` командасын орындаңыз |
| `the attempt produced no result` | Шешім қосылмады немесе құлады. `--logs` кілтімен шығатын мәтінді қараңыз |
| `the solution did not exit when the attempt ended` | Әрекет аяқталғаннан кейін бағдарлама өзі жұмысын аяқтамады |
| `pip install` кезіндегі немесе ұшу кезінде салмақтарды жүктеудегі қате | Контейнерде интернет жоқ. Бәрін `Dockerfile` ішінде орнатыңыз |
