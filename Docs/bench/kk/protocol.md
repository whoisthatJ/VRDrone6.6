# Ushqyr AI Bench: желілік протокол, 1-нұсқа

> Аударма ана тілді маманның тексеруін қажет етеді. Негізгі мәтін: орыс тіліндегі нұсқа.

Python SDK (`bench/sdk/python`) осы протоколмен сөйлеседі. Протокол клиентті кез келген тілде жазуға болатындай етіп
сипатталған. Ол синхронды режимді, нақты уақыт режимін және барлық датчикті қамтиды. Нұсқа нөмірі тек бар хабар өзгерген
жағдайда ғана көтеріледі.

## Транспорт

- TCP. Симулятор **5757** портын тыңдайды (ережелер файлындағы `port` немесе `-bench-port`). Ол `-bench-listen-all`
  кілтімен іске қосылмаса, тек осы компьютерде тыңдайды.
- Бір уақытта бір бағдарлама. Жаңа қосылым ескісін алмастырады.
- Клиентте Нейгл алгоритмін өшіріңіз (`TCP_NODELAY`).

## Фрейм

Екі бағытта да бірдей фрейм қолданылады. Барлық бүтін сандар little-endian түрінде.

| Байт саны | Өріс | Мағынасы |
|---|---|---|
| 4 | `length` | Одан кейін келетін байттар саны (түр + тақырып ұзындығы + тақырып + жүктеме) |
| 1 | `type` | Хабар нөмірі, төменде қараңыз |
| 4 | `header_length` | Тақырыптың өлшемі |
| `header_length` | `header` | Кілттері жол болатын [MessagePack](https://msgpack.org) картасы (map) |
| қалғаны | `payload` | Шикі байттар; олардың орналасуын тақырып сипаттайды |

Симулятор қабылдайтын деректердің шектері: фрейм ең көбі **16 КиБ**, тақырыптың кірістірілуі ең көбі 8 деңгей, бір
картада немесе массивте ең көбі 256 элемент, жолдар ең көбі 4096 байт. Шекті бұзатын фрейм, карта болмайтын тақырып
немесе жауапсыз қалған 64-тен көп хабар қосылымды жабады.

## Хабарлар

| № | Атауы | Бағыты | Жаттығу | Жарыс |
|---|---|---|---|---|
| 1 | `HELLO` | бағдарлама → симулятор | иә | иә |
| 2 | `START` | бағдарлама → симулятор | иә | иә, бір рет |
| 3 | `STEP` | бағдарлама → симулятор | иә | иә |
| 4 | `RESET` | бағдарлама → симулятор | иә | **жоқ** |
| 5 | `DONE` | бағдарлама → симулятор | иә | иә |
| 6 | `PING` | бағдарлама → симулятор | иә | **жоқ** |
| 129 | `WELCOME` | симулятор → бағдарлама | | |
| 130 | `OBSERVATION` | симулятор → бағдарлама | | |
| 131 | `PONG` | симулятор → бағдарлама | | |
| 132 | `ERROR` | симулятор → бағдарлама | | |

Режим рұқсат етпейтін хабарға, белгісіз хабар нөміріне немесе `HELLO` хабарына дейін келген кез келген нәрсеге `ERROR`
жауабы беріледі, және қосылым жабылады. Режимді симулятор белгілейді; бағдарлама жіберетін ешнәрсе оны өзгерте алмайды.

### HELLO → WELCOME

`HELLO` тақырыбы:

| Кілт | Түрі | Мағынасы |
|---|---|---|
| `proto` | int | `1` болуы керек |
| `token` | str | Симулятордың токені берілген болса, соған сәйкес келуі керек |
| `client` | str | Симулятор журналына арналған еркін мәтін |
| `truth` | bool | Тек жаттығу: әр бақылауға шынайы координаталарды қосу |
| `pace` | bool | Тек жаттығу: `false` симуляцияға компьютер мүмкіндік беретін ең жоғары жылдамдықпен жүруге рұқсат береді |

`WELCOME` тақырыбы:

| Кілт | Мағынасы |
|---|---|
| `proto` | `1` |
| `mode` | `"training"` немесе `"competition"` |
| `track` | Тек жаттығу: жүктелген трасса файлының `id` және `hash` мәндері. Жарыс режимінде ешқашан жіберілмейді |
| `sim` | Симулятор нұсқасы |
| `time_mode` | `"sync"` немесе `"realtime"` («Нақты уақыт режимі» бөлімін қараңыз) |
| `control_hz` | Симулятор уақытының бір секундындағы қадам саны (әдепкі мән 100): бір `STEP` уақытты `1 / control_hz` шамасына жылжытады |
| `time_limit` | Әрекеттің уақыт шегі, секундпен |
| `drone` | `class` (`"ai_mission"`: ұйымдастырушылардың вупері; `"ai_core"`: команданың өз файлындағы дроны), `name`, `calibrated` (false = вупердің уақытша моделі) |
| `rc` | `channels` (16), `rate_hz`, `latency_ms`, `failsafe_ms` |
| `sensors.camera` | `width`, `height`, `fps`, `format` (`"rgb8"`), `hfov_deg` (шетінен шетіне дейін), `tilt_deg` (жоғары қарай еңкею), `latency_ms`, ішкі параметрлер `fx`, `fy`, `cx`, `cy` пиксельмен, `distortion` (`model: "radial_k1"`, `k1`), `mount` (корпус жүйесіндегі орны, метрмен) |
| `sensors.lidar` | `rate_hz`, `rays`, `min_m`, `max_m`, `angle_step_deg`. Дронда лидар болмаса, бұл кілт жоқ |
| `sensors.imu` | `rate_hz`, `frame` |
| `sensors.tof` | `rate_hz`, `min_m`, `max_m`, `direction` (`"down"`) |
| `sensors.battery` | `rate_hz`, `cells` |

### START / RESET → OBSERVATION

Екеуі де дронды старт алаңына қояды, симулятор уақытын нөлге қояды және бірінші бақылаумен жауап береді. Бұл бақылауда
дәл сол сәтте түсірілген камера кадры болады. `START` тақырыбы бос. `RESET` (жаттығу) `seed` (int) кілтін тасымалдай
алады: бұл датчик шуының тұқымы (seed). Жарыс режимінде `START` бір қосылымда бір рет қабылданады.

### STEP → OBSERVATION

`STEP` тақырыбы: `rc`, 16-ға дейін саннан тұратын массив, микросекундпен берілген RC арналары (1000-нан 2000-ға дейін):

| Индекс | Арна | Мағынасы |
|---|---|---|
| 0 | Roll | 1500 орта, 2000 = оңға |
| 1 | Pitch | 1500 орта, 2000 = алға (тұмсық төмен) |
| 2 | Throttle | 1000 = нөл, 2000 = толық |
| 3 | Yaw | 1500 орта, 2000 = оңға (жоғарыдан қарағанда сағат тілімен) |
| 4 | AUX1, арминг | 1500-ден жоғары = арминг қосулы. Ұшу контроллері тек осы арна **газ 1050 немесе одан төмен болған кезде** жоғары көтерілгенде ғана арминг жасайды |
| 5 | AUX2, ұшу режимі | 1300-ден төмен Angle (өзі тегістеледі), 1300-ден 1700-ге дейін Horizon, 1700-ден жоғары Acro |
| 6–15 | қосалқы | еленбейді |

1000–2000 аралығынан тыс мәндер осы аралыққа қиылады; жоқ арналар ортаға қойылады (газ бен AUX төмен). Ішінде шекті
сандардан басқа нәрсе бар массив тұтасымен тасталады, оны байланыс арнасы жоғалған пакет ретінде көреді. `rc` кілті жоқ
`STEP` симуляцияны пакетсіз жылжытады (сол жоғалған пакет, бірақ әдейі).

Симулятор пакетті байланыс арнасының моделі арқылы жібереді (тұрақты кідіріс `latency_ms`; `failsafe_ms` бойы пакет
болмаса, AUX1 өшіріліп, қайта қосылғанша моторлар өшеді), адам-пилот ұшатын дәл сол ұшу контроллерімен және ұшу моделімен
тура бір басқару кезеңіне алға жылжиды және жауап береді. Әрекет жүріп жатпаған кезде `STEP` ештеңені өзгертпейді және
ағымдағы бақылауды қайтарады.

### OBSERVATION

Тақырып:

| Кілт | Түрі | Қашан бар | Мағынасы |
|---|---|---|---|
| `t` | float | әрқашан | Старт сигналынан бергі симулятор уақыты (с) |
| `tick` | int | әрқашан | Старт сигналынан бергі физика қадамдары (1 кГц) |
| `running` | bool | әрқашан | Әрекет аяқталған соң false |
| `status` | str | әрқашан | `running` немесе аяқталу себебі: `finished`, `time_limit`, `stuck`, `disconnected` |
| `imu_n` | int | әрқашан | Жүктемедегі IMU өлшемдерінің саны |
| `tof` | map | жаңа өлшем болғанда | `t`, `range` (м), `valid` (диапазоннан тыс болса false; сонда `range` 0 болады) |
| `battery` | map | жаңа өлшем болғанда | `t`, `voltage` (В) |
| `lidar` | map | толық айналым аяқталғанда | `t` (айналымның соңы), `n` (сәулелер) |
| `camera` | map | жаңа кадр болғанда | `t` (кадр түсірілген уақыт), `seq`, `size` (байт) |
| `truth` | map | жаттығу, сұралған болса | `position` және `velocity` [шығыс, солтүстік, жоғары] түрінде метрмен, `points`, `score_time` |

Жүктеме, мына ретпен:

1. `imu_n` × 7 `float32`: `t, gx, gy, gz, ax, ay, az`.
2. `lidar` бар болса: метрмен берілген `n` `float32` қашықтық; 0 = ештеңе өлшенбеген.
3. `camera` бар болса: `size` байт, `height` × `width` × 3, RGB, жоғарғы жол бірінші.

**Камера объективі.** Кескінде бөшке тәрізді бұрмалану бар. `x_d = (u - cx) / fx`, `y_d = (v - cy) / fy` және
`r² = x_d² + y_d²` болсын. Сонда шынайы бұрыштардың тангенстері: `x_u = x_d (1 + k1 r²)`, `y_u = y_d (1 + k1 r²)`
(оңға және төмен қарай оң). `k1 = 0` кәдімгі перспективалық кескінді білдіреді.

**Камераның бейне арнасы.** Кадрлар аналогтық бейне байланысының моделінен өтеді: жұмсақ бөлшектер, жайылған және
жылжымалы түс, шу, секіретін жолдар және үзілген жолақтар. Старт алаңынан (қабылдағыш сонда тұр) алыстаған сайын және
арада қатты кедергі болғанда кескін нашарлайды. Камера сонымен қатар экспозициясын сахнаға бейімдейді.

**Лидар.** Дронның өз көлденең жазықтығындағы 2D сканер. `k` сәулесі «алға» осінен `k * angle_step_deg` бұрышқа, солға
қарай (жоғарыдан қарағанда сағат тіліне қарсы) бағытталған. Бір айналымның сәулелері дрон қозғалып бара жатқанда бірінен
кейін бірі түсіріледі, сондықтан ұшу кезінде түсірілген скан соған сәйкес қисайған.

**Координаталар жүйелері мен осьтер.** Корпус жүйесі: x алға, y солға, z жоғары, оң жақты жүйе. Гироскоп рад/с-пен
(x: оңға крен +, y: тұмсық төмен +, z: солға рыскание +). Акселерометр м/с²-пен, үлестік күш ретінде: тыныштықта және
тегіс тұрғанда ол (0, 0, +9,81) көрсетеді.

**Уақыт.** Барлық уақыт симулятор уақыты. Камера кадры түсірілгеннен кейін `latency_ms` өткен соң жеткізіледі.
Датчиктер өз жиіліктерін сақтайды (әдепкі бойынша камера 30 Гц, IMU 500 Гц, ToF 50 Гц, батарея 10 Гц), сондықтан
бақылаулардың көбінде тек IMU өлшемдері болады.

**Жарыс режимінде ешқашан жіберілмейтін нәрселер:** орын, жылдамдық, бағдар, қақпалардың орындары, трасса атауы, есеп.

### DONE → OBSERVATION

Бағдарлама жұмысын бітіргенін айтады. Әрекет `finished` статусымен аяқталады.

### PING → PONG (жаттығу)

`PING` тақырыбы: `payload` (int, ең көбі 4 МиБ). `PONG` сонша байтпен қайтып келеді. Транспортты өлшеуге арналған.

### ERROR

Тақырып: `code` және `message`. Кодтар: `hello_first`, `protocol`, `token`, `not_allowed`, `already_started`,
`attempt_over`, `unknown_message`. `ERROR` хабарынан кейін қосылым жабылады.

## Жарыс режимі

Симулятордың бір іске қосылуы бір әрекет. Бағдарлама `connect_timeout` секунд ішінде (әдепкі мән 60) қосылып, `START`
жіберуі керек және әр бақылауға нақты уақыттың `step_timeout` секунды ішінде (әдепкі мән 10) жауап беруі керек; әйтпесе
әрекет `timeout` статусымен аяқталады. Бағдарлама кетіп қалса немесе оған бас тартылса, әрекет `disconnected` статусымен
аяқталады. Әрекеттен кейін `HELLO` хабарына `attempt_over` жауабы беріледі. Бағдарлама көре алатын `status` мәндері:
`running`, `finished`, `time_limit`, `stuck`.

## Нақты уақыт режимі

Ережелерде `time_mode: "realtime"` тұрса, симулятор нақты сағат бойынша жүреді және ешкімді күтпейді. Бұл кезде `STEP`
тек пакетті байланыс арнасына береді; `OBSERVATION` бағдарлама сұраса да, сұрамаса да әр басқару кезеңінен кейін
жіберіледі. Бағдарлама келген нәрсенің бәрін оқып, ең жаңа бақылау бойынша әрекет етуі керек (SDK-дегі `step()` және
`latest()` осыны істейді). Оқуды тоқтатқан бағдарлама жіберу буфері толғанда ажыратылады. Нақты уақыт режиміндегі ұшулар
қайталанбайды; `result.json` уақыт режимін жазып алады.

## Детерминизм

Симулятор уақыты тек `STEP` хабарымен алға жылжиды. Бірдей жинақ, трасса, тұқым (seed) және `STEP` хабарларының бірдей
тізбегі бірдей типтегі компьютерде бірдей ұшуды және бірдей есепті береді. Бағдарламаның жылдамдығы мен машинаға түсетін
жүктеме бұған әсер етпейді.
