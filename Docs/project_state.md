# Project state before the Track & Garage work (2026-11-02)

Branch `feature/track-garage` (from `feature/pc-radiomaster-pocket` @ a2a06e6). Unity **6000.6.0f1**, URP 17.6,
Input System 1.20, Windows/DX11, Mono. Editor driven through the Unity CLI (`unity command eval`).

## What exists
| Area | State |
|---|---|
| Flight model | Plain C# in `Scripts/Flight` (`QuadSimulator`, `QuadProfile`, `MotorModel`, `AeroModel`, `BatteryModel`, `PidController`, `Mixer`, `RateProfile`). Deterministic, sub-stepped by `QuadVehicle`. **`FLIGHT_PHYSICS.md` is not in the repo**; the code is the reference. |
| Quads | `QuadCatalog` with 3 classes (race5, freestyle5, whoop65) as `QuadProfileAsset`s; the quad visual is primitives + library materials. No parts/garage system. |
| Input | Radio (`RcRadioSource` via `RadioDeviceProvider`: Windows HID reader on PC, Input System, Android raw), presets + calibration wizard, keyboard/gamepad, Touch controllers; all connected sources are mixed (`VehicleInputRouter`). Invert pitch/roll settings. |
| Race | `RaceSession` (countdown, laps, wrong-gate warning, results), `Gate` + `GateCrossing` (directional plane crossing), `LapTimer`, `LocalLeaderboard`, `GhostSystem`, `RaceAutopilot`. |
| Tracks | Gate-list JSON (`TrackData`: spawn, gates, props, laps) in `Data/Tracks`, `TrackCatalog`, `TrackLibrary` (user tracks), `TrackLoader`. **No splines**, no lane lights/chevrons/supports. |
| Track editor | `TrackEditorController` (VR controllers with a mouse/keyboard desktop fallback), `TrackEditModel` (pure, tested). |
| Scenes | Boot, Menu (pit tent at dusk), Track_Field, Track_Hangar, Track_Industrial, InputDiagnostics. All generated by `Editor/Builders/*SceneBuilder.cs`, then dressed by the art pass (`Editor/Art/*`, *Tools > Art > Rebuild Everything*). |
| Cameras | `ViewModeManager` with VR modes Goggles / Immersive / Line-of-sight, `FpvCamera` (tilt 0–60°, horizontal FOV 90–150°), `GogglesScreen` + `VtxSignal` analog feed, `ComfortVignette`, `HorizonRing`. On PC (no XR) Goggles/Immersive fall back to the drone camera. **No Cinemachine, no chase cam.** |
| HUD | `OsdHud` (battery V/cell/mAh, mode/armed, armed timer, throttle, speed/alt, LQ, crosshair, horizon, warnings) and `RaceHud` (lap info, countdown, results text panel) on a uGUI canvas rendered by the FPV camera; head-locked VR HUD. |
| UI | Code-built **uGUI + TextMeshPro** (`UiKit`, `MenuController` world-space panel with XRI laser pointers + mouse). No UI Toolkit. |
| Graphics | `GraphicsQuality` presets **Medium / High / Ultra** (+ render scale, AA, shadows, SSAO, vegetation, post, VSync). No Low preset, no frame cap. |
| Build | `GateRush/Build/Build Windows (PC)` → `Builds/Windows/GateRush.exe` (Standalone without the OpenXR loader); Quest APK build still present. |
| Tests | EditMode only, ~127 test methods (flight, rates, battery, radio, race, tracks, editor model, settings, content, PC platform). |
| Art | CC0 Poly Haven / ambientCG assets, licence log in `Assets/_Project/Art/ASSET_LICENSES.md`, procedural meshes and textures from `Editor/Art`. |

## Conflicts with the plan
| Plan says | Project has | Resolution |
|---|---|---|
| No VR | Whole VR stack (XR rig in every scene, Touch input, goggles room, comfort settings, VR track editor) | T0 removes the packages, rigs, Touch source and comfort/goggles code; the track editor keeps its existing mouse/keyboard mode. |
| UI Toolkit menus | uGUI + TMP, built from code | New screens (results, garage) in UI Toolkit; existing menus stay uGUI until they are redone (decision logged in TRACK_GARAGE_PLAN.md). |
| `FLIGHT_PHYSICS.md` | Not present | Use `Scripts/Flight` + PLAN.md §4 as the physics reference. |
| Track = spline + obstacle list | Track = gate list JSON | T1 adds `TrackDefinition` next to `TrackData`; existing tracks keep working. |
| Quality Low/Medium/High/Ultra | Medium/High/Ultra | T0 adds Low. |
| Gates are checkpoints by route distance | Gates ordered by list index | T1 orders checkpoints by distance along the spline. |
